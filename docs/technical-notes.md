# Technical notes

This is the engineering log the previewer was built against: what each subsystem reads, which engine behaviour it copies, what was verified and how, and what is still approximate. It is long and written for people changing the code. For how to use the program, start at the [README](../README.md).

Some verification entries name test scenes, sample files and checks that have since been removed from the project (a Braver impact sample and its exporter, a scripted Cross Slash dialog, Cloud trail captures). Those entries are kept because the engine findings in them still hold. Paths under `verification/` and `test-data/` refer to local folders that are not in the repository. Where an entry mentions `PluginTemplate`, `DirectXTex` or `DirectXTextWrapper` folders in a workspace, that source is now under `engine` and `native`.

Run **SSE Animation Previewer.exe** from the portable folder. Keep the entire folder together. It includes the .NET desktop runtime, animation/NIF/archive libraries, DDS decoder, and native C++ runtime. No separate .NET installation, converter, Maya, Blender, SKSE installation, or development tool is required to launch it.

This is a development preview. Animation selection and decoding, character meshes, root motion and some mesh-based effects work. **It does not yet reproduce all Skyrim particle systems or all effect triggers accurately.** See the limitations below before relying on its visual output.

## Start
1. Choose **Open Data** and select your Skyrim Data folder. Base-game meshes and textures are needed even when testing a small mod.
2. Choose **Add mod folder** for loose-file overrides; later folders win. Adding a folder keeps the selected race, sex, weapon, head parts and worn armor; a selection whose record is no longer loaded falls back to the default and is noted in diagnostics. The **Loaded sources** list under the animation library shows every mounted folder in precedence order, with its loose-file and BSA counts, the selected plugins.txt and any dropped animations. Double-click a folder to open it in Explorer; right-click to copy its path or remove it and reload the rest.
3. Use **Load order** to select your active plugins.txt, especially with a modded installation.
4. Select a race, sex and head parts, equip armor by slot, and choose a weapon.
5. Select an animation in the library or drag HKX files/folders onto the list.

A mod folder alone can load its animations but cannot supply missing base-game assets. The application does not download game files or ship Bethesda assets.

For MO2, add the portable EXE as an executable yourself, run it through MO2, and select the virtual game Data folder and that profile's plugins.txt. MO2 has not been launched or validated by this development task. The application uses normal filesystem access so it can receive MO2's virtual files.

## Controls
- Alt + left drag: orbit; Alt + middle drag: pan; Alt + right drag or wheel: dolly.
- F: frame current animated meshes and live particles. Space or the playback button: play/pause.
- Loop, root motion and effects are enabled by default.
- Step FPS defaults to 30 and controls previous/next-frame stepping. Continuous playback evaluates elapsed seconds independently of this setting, with scene updates and presentation capped at 60 FPS. Actual throughput depends on rendering cost and Windows timer scheduling; 60 FPS is a ceiling, not a guaranteed sustained rate.
- The timeline is a tall bar with a large scrubber. Click anywhere on it to move the scrubber and the pose to that point, and keep the button held to scrub; playback pauses while you hold it and resumes on release if it was playing. With the timeline focused, the Left and Right keys nudge it by half a percent, Page Up and Page Down by a tenth, and Home and End jump to the ends.
- Use the timeline to scrub and the arrow buttons to step. The readout beside the controls shows the time and the frame number (frame 0 is the first pose, counted at the Step FPS rate).
- **Animation queue** plays several clips one after another on one timeline. Add clips from the Queue tab under the viewport: drag them in from the library, right-click and choose Add to queue, or select and press Add selected clips. Ctrl+click marks several library clips and Shift+click marks a range; dragging any marked clip brings all of them, in library order. Dragging a folder or group node brings every clip beneath it. The list shows the play order, top first, with each clip's start and end time, its root motion and any MCO speed. Drag a queued clip to move it, or use Up and Down; double-click one to jump to it. While you drag, the clip being moved has a white outline and a white line marks where the drop will insert, including for clips dragged in from the library. Open in window puts the list in its own resizable window; Dock back in tab returns it. Press Play queue to play. Selecting a single clip in the library plays that clip alone and keeps the queue list for later.
  - Root motion carries through the queue. Each clip starts where the previous one left the actor, turned by every rotation so far, so a combo of attacks travels as far as the clips add up to, and a clip after a turn moves along the new facing. Root motion here is the AMR animmotion and animrotation annotations, the same data a single clip uses; a clip without them stays in place.
  - **Next clip starts at**, on by default, hands each queued clip over to the next at an MCO annotation instead of at its end, the way an MCO combo continues when the next attack is pressed. The drop-down picks MCO_WinOpen (default) or MCO_PowerWinOpen. A clip without the chosen annotation plays to its end, and the last clip always does. The outgoing clip's annotations after the hand-over are skipped, so its effects and weapon events stop there, and the next clip's root motion starts from where the actor stands at the hand-over. The queue list shows each clip's hand-over point. A clip that has the chosen annotation at more than one time (not counting copies on another track at the same time) gets a small drop-down right after its file name (the rest of the row moves along to make room), showing the time in use and which occurrence it is, for example "▾ 0.833 s (1/2)". Click it to pick the occurrence the queue hands over at; the first is the default. The choice belongs to that place in the queue, so the same clip queued twice can hand over at different times. MCO_WinOpen and MCO_PowerWinOpen keep separate choices, and the choices are saved with the session. None of the clips in the NordicSoulsPBR list has two different MCO_WinOpen times; `--window-pick-smoke <clip> <next clip>` builds a test copy whose MCO_WinClose is renamed MCO_WinOpen.
  - **Blend (s)**, default 0.30, sets how long each clip blends in from the clip before it, with Havok's smooth ease curve. The outgoing clip keeps playing during the blend and holds its last frame if it runs out. 0 gives a hard cut. The blend changes the pose only: root motion and annotation times are those of the clips themselves.
  - Every MCO_AttackSpeed annotation in a queued clip changes its speed from that point on, as MCO does, and its annotations, effects and root motion move with it. A clip starts at the speed the clip before it ended on, since MCO only resets the value to 1 outside attacks; the Configuration tab says when a clip's first speed was carried over. The Speed box scales the whole queue.
  - The time readout names the clip being played, and Configuration & source lists each clip's start, length, root motion and where it begins. The queue, its blend time and whether it was playing are saved with the session.
  - Not modelled: the game's own transition times and curves come from the behavior graph and can differ from the Blend setting. Looping the queue jumps back to the start without a blend, the same as a single looping clip.
- While **Root motion** is ticked, a small amber arrow (34 units to the tip, about a quarter of a character's height) lies on the ground at the actor root: the point the AMR animmotion and animrotation annotations move, which NPC Root [Root] hangs from. Its base and the short post on it mark that point, and it points along the actor's facing (+Y turned by the accumulated animrotation), so it follows a queue's travel and turns too. Where the character covers it, it shows faintly through. Clearing Root motion removes it.
- **Sounds** (beside Effects, off by default, saved with the session) plays the clip's `SoundPlay.<EditorID>` annotations as playback passes them, once per pass when looping. Scrubbing, seeking and stepping play nothing, and a sound already playing finishes when you pause. The editor ID is looked up the way the game does: a sound descriptor (SNDR) with that ID, or a sound marker (SOUN) that points to one. A file is picked at random from the descriptor's list, and the game's .xwm or .fuz of the same name is used when the listed .wav is absent. Volume is the descriptor's static attenuation (dB), less a random amount up to its dB variance, times the static volume and default menu volume of its category and every parent category. Pitch follows the frequency shift and a random amount within the frequency variance. Not modelled: distance attenuation and 3D position from the output model (sounds play centred), your own volume sliders, conditions (assumed to pass), and looping (a looping descriptor plays once). The Annotations & effects tab lists each sound with what it resolved to.
- **Warnings** lists annotation sounds that cannot play. When no loaded plugin defines an editor ID, the previewer searches the plugins in the other folders next to your mounted mod folders (an MO2 mods directory) and names the plugin and mod folder that has it, for example "FF7CloudAudioSSBU.esp in the mod folder FF7 Cloud Audio - Smash Ultimate". It also reports a descriptor whose category or master plugin is missing, and listed sound files that are not in any mounted folder or archive.
- **Snap to frame** keeps the pose on whole frames: scrubbing lands on the nearest frame, the arrow buttons step one frame from the current one, and playback holds each frame's pose until the next. It is saved with the session.
- Lighting opens the renderer's lighting controls.
- **Sheathed on holster node** moves the weapon from the hand bone to the holster node for its WEAP animation type (WeaponSword, WeaponDagger, WeaponAxe, WeaponMace, WeaponBack for two-handers, WeaponBow, WeaponStaff, WeaponCrossBow), with an identity local transform as the game does. The label shows the node in use; if the mounted skeleton lacks it, the label says so and the hand is used. Weapon-attached particle spawns follow the same bone.
- **Attack speed.** MCO binds the playback speed of every attack clip (normal, power, left-hand, sprint, weapon art and the transitions) to the MCO_AttackSpeed graph variable, and each `PIE.@SGVF|MCO_AttackSpeed|value` annotation sets it; this was checked in the Attack - MCO Updated and Attack MCO-DXP behavior files. The previewer plays a clip the same way: each annotation's speed runs from its time until the next one, so a clip that goes 1.10x, 1.30x, 1.10x plays each stretch at its own rate. Annotations, root motion, sounds, Precision collisions and effects follow that timing. The Speed box is the viewer's own rate on top and starts at 1.00x; the note beside it lists the annotations, the time readout shows the clip time and current rate, and the Annotations tab lists playback times with clip times in brackets. A BFCO_AttackSpeed annotation is listed but not applied, because MCO does not read it and no BFCO behavior is installed in the lists checked. A session saved by an older build that put the first annotation's value into the Speed box comes back at 1.00x. The game applies a new value on the frame after the annotation (about 17 ms at 60 fps); the previewer applies it at the annotation.
- **Weight** (0 to 100) blends the race body and every equipped armor piece between their _0 and _1 meshes, as the game does for actor weight. ARMA records reference the _1 mesh; the previewer loads the _0 counterpart from the mounted assets and interpolates pre-skin vertex positions, so skinning and normals follow. The label under the slider reports how many shapes are blended; a mesh whose counterpart is missing or has a different vertex count stays at its loaded weight and is diagnosed. Default is 100, matching the referenced mesh. Head parts and weapons have no weight pairs.
- **weaponDraw / weaponSheathe.** When the selected clip carries either annotation, the weapon moves between its type's holster node and the hand on the annotation's frame. Before the first annotation it is in the opposite state, so an equip clip starts on the holster and an unequip clip starts in the hand. While such a clip is selected the Sheathed checkbox is locked and shows the annotation times; the Annotations & effects tab lists the schedule. Left-hand and shield draws are not distinguished.
- **Show skeleton** (under CHARACTER, above the race list, off by default) draws every bone of the loaded skeleton, including bones merged in from equipment, as a yellow joint marker with a cyan line to its parent, at the current pose and root motion, over the meshes. **Bones…** opens a pop-up beside the button (Esc closes it) with **Show bone names** (labels beside each joint) and the bone list. With nothing ticked every bone is shown; tick one or more to show only those, each with its local axes (X red, Y green, Z blue). The search box narrows the list, Tick listed and Untick listed apply to what it shows, and Show all clears the selection. The tick box, names and selection are saved with the session. `--skeleton-smoke <clip>` runs 12 checks.
- **Hair color** under the character selectors sets the one hair color the actor carries. The game writes that color into every hair-tint material on the actor (Actor::UpdateHairColor), so it reaches head-part hair, brows and worn hair-tint pieces such as wigs alike. "Race default" uses the race's default color record, or the only color the race offers. The list also holds every CLFM record in the mounted plugins and a custom color picker. The game multiplies the hair texture by the color's bytes over 128: a value of 128 leaves the texture as painted, vanilla colors are darker than that, and a RaceMenu color above 128 brightens it. The previewer cannot read the color stored in a save, so pick the one your character uses. The choice is saved with the session.
- Equipment that covers slot 31 (Hair), such as a helmet or wig, replaces the hair head part and its extra parts, as in game.
- **Simulate HDT-SMP physics** in the PHYSICS group runs cloth, hair and strap physics for every loaded item that carries a physics XML. It is off by default and saved with the session. The HDT-SMP physics section below covers the overlay toggles and what the simulation reads.
- **Show Precision attack collisions** in the PRECISION group draws the capsules Precision creates from the clip's `Collision_*` annotations. It is off by default and saved with the session. The Precision attack collisions section below covers the rules and sizes.
- **Equipment slots.** The slot list starts with All slots, which lists every armor in the loaded plugins. Slots 44 to 60 show the usage the Nexus wiki body-part list suggests in parentheses, for example 45 · (neck: cape, scarf, shawl, neck-tie). A filter typed in the armor list stays when you switch slots, and the first matching armor is picked.
- **Show weapon** under the weapon selector hides or restores the equipped weapon meshes without rebuilding the scene. Weapon-attached particle spawns and weapon-node following keep working while the weapon is hidden. The setting is saved with the session.
- Every drop-down list opens with a filter box. Type to narrow the entries (all words must match), use the arrow keys or the mouse to pick one, and press Enter or Escape. F4 or Alt+Down opens the list from the keyboard.
- **Grid floor at origin** draws a circular grid platform at Z = 0, the level the skeleton root stands on. Cells are 64 game units (a character is about 128 tall); the disc is roughly 6,000 units across (half again as wide as before) with a dithered edge. The floor is drawn before scene meshes so blended effects and particles compose over it. It is excluded from framing and from the effect diagnostics, and the setting is saved with the session.
- Effect sequence selects a NIF sequence explicitly, or follows Start/Begin to Loop automatically (including mBegin/mLoop names).
- The tabs under the viewport use the dark theme with bold headers and one colour each: blue Configuration & source, green Annotations & effects, amber Diagnostics, red Warnings, purple Queue. The open tab joins the page below it with a bar in its colour; Diagnostics, Warnings and Queue show how many entries they hold. In a narrow window the tabs wrap onto more rows.
- **Playing clip and overrides.** In the animation library the row of the clip that is playing is green, wherever the tree selection is. It is orange instead when an enabled OAR or DAR folder with a higher priority holds the same animation file, since that folder can replace the clip in game. A plain (non-replacer) file counts every enabled replacer folder that holds it. Hover any clip to list the overriding submods with their priorities and folders (the first eight; Configuration & source lists all of them for the playing clip). Two clips compete when they stand in for the same file, so a `_variants_` folder counts for the file it replaces and a submod using overrideAnimationsFolder counts under its own priority. Disabled submods are left out, a clip's own submod and equal priorities do not count, and conditions are not evaluated, so an orange row means the clip can lose, not that it does. Checks: `--catalog-test` (6 override checks on verification/catalog-fixture) and `--override-smoke` (8 checks on the drawn row colours and the hover text); evidence in verification/library-overrides.
- **Active annotations.** In Annotations & effects, the annotations that are active at the current time are highlighted in green, and the highlight moves as the time slider advances. An ordinary annotation is active from when it fires until the next annotation fires; annotations at the same time are active together. These last longer: MCO_nextattack and MCO_nextpowerattack until the next one of the same kind, MCO_WinOpen until MCO_WinClose (and the close until the next open; the same for the power window), MCO_AttackSpeed until the next MCO_AttackSpeed, a Collision_Add for as long as Precision keeps that collision alive, Collision_AttackStart until the attack ends (Collision_AttackEnd, Collision_Cancel, attackStop or staggerStart), and other Collision_ annotations until the next Collision_ annotation. BFCO's window, next-attack and speed annotations follow the same rules. AMR's animmotion and animrotation keys sit on almost every frame, so they do not end other annotations; the latest key of each is highlighted. In a queue, annotations after a clip's hand-over never fire and are never highlighted. During playback the list scrolls to keep the latest annotation in view; when paused it stays where you put it, and your text selection is kept. `--annotation-smoke <clip>` runs 12 checks.
- Configuration & source shows replacer configuration and source paths. Annotations & effects shows HKX events and resolved effects. Diagnostics reports missing and unsupported content.
- Restore session remounts saved source folders and load order. Character equipment is not currently persisted.

## Compatibility and known limitations
- Direct decoding supports the tested Skyrim SE spline and interleaved HKX animations, in packfile form or in Havok binary tagfile form (see below). Legacy 32-bit Skyrim files and behavior files are not universally supported.
- OAR/DAR folder discovery and configuration inspection do not run the frameworks' condition engines.
- AMR translation/rotation annotations are interpolated. Character behavior graphs and gameplay collision are not executed; the validated effect-sequence subset described below is supported.
- Payload aliases, delayed payloads, spell/projectile models, selected NIF controllers, DAC event configurations and manual key-util spell triggers are inspected/resolved. Actor conditions are assumed only where indicated; gameplay scripts and key-state behavior are not executed.
- NiParticleSystem box/sphere/cylinder and mesh-surface emission now runs at a deterministic 120 Hz, with lifetime, spawn-on-death generations, gravity, generation-specific growth/fade, color, rotation and texture-frame handling. Rendering uses authored DDS billboards and blend settings. Mesh emitters sample NIF-contained animated bone deformation at each birth time. External actor skeleton binding, native skinning parity, specialized strip/mesh particles, particle-shader distortion and several controller/modifier cases remain unsupported or approximate. Diagnostics identify unsupported blocks; visual equivalence with Skyrim is not established.
- Projectile origins/attachments, hit events, spell art placement and lifetimes still need engine comparisons.
- Race morphs, armor alternate texture-set overrides, partial mesh-partition hiding, addon priority conflicts, and all equipment attachment cases need additional work.
- Added mod folders mount top-level BSA archives and loose files. Loose files take precedence; later folders replace same-named archives as a whole. Without a selected profile, standalone archives load in folder-add order, then filename order. Selecting plugins.txt applies the resolved active plugin order to standard paired BSAs, with adjacent Skyrim.ini archive lists first; missing INI keys use SE defaults and are diagnosed. Inactive/unlisted archives are excluded. Archive changes also refresh cached viewport textures. For a selected base folder named Data, Skyrim.ccc beside that folder supplies implicit Creation Club plugins before starred profile entries; missing entries are diagnosed. Overlay folders cannot select another installation's list. Custom archive-loader behavior still needs separate validation.
- The grid floor is a preview aid, not game geometry: it casts no shadows, receives none, and particle collision ignores it.
- Some renderer dialogs retain upstream labels/style.
- Modern Windows x64 and a functioning OpenGL graphics driver are required. Portable deployment was checked on this machine, not a clean VM.

## Effect preview fixes
Direct NIF previews now advance mesh and particle controllers, including controller-manager multi-target transforms and alpha-test thresholds. Unshaded emitter source meshes are excluded from visible artwork. Authored zero-scale frames are skipped safely, author-machine texture paths resolve through mounted Data, and effect previews start at an oblique angle to make flat cards visible.

The Anchor Cross Slash and Blade Beam regression renders cover CrossSlash_HitFX01, CrossSlash_HitFX02, Fenrir_BladeBeam, and BladeBeam_StartFX. This does not establish support for every effect in the mod. Some NIFs have unbound mesh-emitter references that require runtime target geometry. Death-triggered and collider-triggered spawning are supported; lag-bone motion and refraction remain incomplete. Lighting-shader refraction meshes now use a separate distortion buffer and scene-color composition pass, including Anchor's Refract and swdflashB layers. The pass uses the authored diffuse-slot distortion texture, UV transforms, vertex alpha when VertexColors is enabled, refraction strength, clamp and angular-falloff flags, posed vertices and scene depth. BSEffectShaderProperty distortion remains unsupported and diagnosed. The native BSFadeNode refraction fade equation is implemented using default fade category 0 and a preview model-bounds center; game-assigned categories, INI overrides and native bound merging remain unverified and are diagnosed; translucent pass ordering, native buffer precision, all skin-normal cases and game parity remain unverified. The controlled fixture verifies zero-strength identity, visible displacement, opaque occlusion, signed strength and identical replay. See verification/refraction-pass.

Directional drag now follows the AE capped linear formula: it removes min(1, Percentage × 30 × elapsed time × range weight) of axial velocity. Its range weight decreases linearly between Range and RangeFalloff; scene transforms and update cadence still need Skyrim comparison. Particle alpha-test comparisons, UV transforms/wrapping and depth-test/write flags now follow their native fields. Self-target spell hit art uses paired EFIT durations and follows actor root motion; actor-surface effect shaders are not yet rendered.

## Verification
The five supplied mod folders produced 942 decoded animations and 186 loaded NIF files. Ten animations were unsupported at the time (nine non-packfile files, one legacy 32-bit file); the nine non-packfile files are Havok binary tagfiles and now decode through the converter described below, leaving the one legacy 32-bit file. These are parser checks, not a claim that every animation or effect renders correctly.

The Cloud test scene was also rendered in the actual viewport. These checks caught and fixed an overflow in material/controller handling and an incorrect model/view transform order. The standalone runtime trace confirms local coreclr.dll was loaded. MO2 virtual-file tests and Skyrim visual comparisons remain outstanding.

Attack speed: `--particle-test` includes 5 speed-map checks (every annotation read, BFCO kept apart, a three-change clip mapped piece by piece, speed carried into the next queued clip, a single clip becoming a one-clip timeline). `--speed-smoke <clip> <plain clip>` on Cloud Fenrir's mco_powerattack1 (1.10x at 0.06 s, 1.30x at 0.32 s, 1.10x at 1.30 s) checks that 3.000 s of clip plays in 2.596 s, the value summed piece by piece, and that the last annotation fires, and poses, at its mapped time.

Annotation sounds: `--sound-smoke` runs 23 checks on the NordicSoulsPBR list. On an MCO battleaxe power attack, vanilla WPNSwingUnarmed resolves through Skyrim.esm to two .wav files in Skyrim - Sounds.bsa, at gain 0.81 (0 dB static attenuation, category volume 0.81). The test plays the clip through and checks that each of its 2 annotations plays once at its time, then 6 plays over 3 looped passes, and none while scrubbing. The FF7 sprint attack's SSBU sounds raise warnings that name FF7CloudAudioSSBU.esp in the FF7 Cloud Audio - Smash Ultimate folder; once that folder is mounted, they resolve and decode. An .xwm decodes through Windows' WMA decoder to the same length as ffmpeg's output (247,808 frames for a 5.6 s stereo file), and the audio device opens. The mix is checked offline so the test makes no noise.

Private game fixtures and test renders stay outside the portable distribution. The original Braver test assets are included; no Bethesda or third-party mod assets are bundled.

## Animation library inspection
DAR groups identify their mounted source mod and numeric priority. OAR groups include author mod/submod names, active user-data priority, and explicit variant folders. Variant weights, play-once flags and disabled state are displayed; disabled entries remain manually previewable. Selecting a group displays its configuration without playing a clip. The Expand / search button opens a larger searchable reader for configurations, annotations or diagnostics.

Author config.json and active user.json data are shown separately, following OAR's distinction between author metadata and user-controlled data. Dragged HKX files retain DAR/OAR context when their original folders contain it. Source labels use mounted roots or archive paths; a merged/MO2 virtual Data path does not reveal an original mod name automatically. Relative shared-folder overrides are resolved into each owning configuration group, including user rerouting and variants. Absolute overrides outside mounted virtual Data are diagnosed. Game actor condition evaluation and runtime variant scheduling remain incomplete.

## Character assembly
Head-part filtering uses the native male/female flags, starts with the race's own gendered HEAD defaults, and loads linked extra parts such as hairlines. Selecting a different face, eye, hair or eyebrow part replaces the previous choice of that type. Head-part texture sets and hair-color records are applied to their materials. Equipped race-compatible armor addons replace matching race-skin addons; uncovered hands and feet remain visible. More complex partition/priority rules and helmet/head-part suppression still need work.

## Particle spawn placement
Payload Interpreter particle cues preserve their biped index and spawn flags. Initial spawn placement uses the selected part's animated geometry bounds at the annotation time, including weapon rotation and local offsets. Missing equipped parts suppress the effect with a diagnostic. Temporary particle effects now retain their initial target-relative offset and follow the animated weapon node, independent of spawn flags, as AE does when a target is supplied. Nonweapon equipment currently follows the actor root. Exact partClone nodes, runtime NiBound centers, other spawn-flag effects remain unfinished. PI temporary effects expire when age exceeds lifetime, removing surviving particles; zero/negative lifetimes are not treated as infinite. Native asynchronous load timing and manager scheduling remain unverified.

## Dense mod effects: performance, particle budget, missing alpha properties
Anchor's effect NIFs author birth rates of 9,999 particles per second against NiPSysData limits of 9,999, and AxeWeaponSpark.nif runs three such systems at once. Skyrim's native update handles that; the previewer's simulation is managed code and resolved every modifier parameter through reflection for every particle at every 120 Hz step, so those clips took 200 to 600 ms per frame. Three changes:
- Modifier parameters, emitter placement and the per-step predicates are now resolved once per simulation step (the native update also evaluates them per update, not per particle); the per-particle loop is arithmetic. The billboard pass writes into a reusable vertex buffer and sorts by precomputed depth.
- **Particle budget** (right panel, default 2,000 live particles per system, 0 = authored limit only) caps each system below its NiPSysData limit. Births over the budget are counted in the status line and listed in Diagnostics with the authored limit, so the trade is visible. The setting is saved with the session.
- A NiParticleSystem with a BSEffectShaderProperty and **no NiAlphaProperty** used to render as opaque quads (black or white blocks; ActorJumpStartSmoke.nif's SuperSpray03 is the case you reported). Every one of the 313 vanilla magic particle systems ships an alpha property, 287 of them with flags 4109 (additive SrcAlpha/One, no test), so the preview now assumes that default for a missing property and says so in Diagnostics. Skyrim's actual handling of the missing property is unverified.

Casting art (MGEF DATA offset 92) is now parented to NPC R MagicNode [RMag] as the game does for the casting hand; left-hand, dual and staff casts are not distinguished. Effect NIFs whose behavior graph is unsupported (Magic\CastingWithIntro.hkx) no longer freeze on the first sequence: the automatic path treats mIntro like Begin and mIdle like Loop, so HealFXHand01 keeps animating instead of showing a still frame.

## One-shot effect controllers (flags 69)
One-shot effects save their controllers as APP_INIT with the active bit clear (TimeControllerFlags 69). Every manager-less vanilla impact emitter surveyed uses it (17 controllers in ten files such as icicleimpact01.nif), as do mod impacts (Critical Hit VFX, Dynamic Impact) and FF7 Limit Gauge's aura NIFs. The previewer required the active bit, so these effects emitted nothing and raised no diagnostic. A preview starts at effect time zero, so APP_INIT controllers now count as started for emitters, lag-bone controllers and mesh-particle template chains. APP_TIME controllers saved inactive (68) stay off, and controllers under a NiControllerManager are unchanged (all surveyed ones carry the active bit). That the engine sets the active bit at spawn is inferred from Gamebryo's StartAnimations, not read from the 1.6.1170 executable.

Verification: Critical.nif and LimitChargeAura.nif went from zero particles to 78 and 95 live at their peaks; renders and logs for old and new builds are in verification/one-shot-controllers. ## Baked flipbook effects and repeated triggers
Some effects are exported as baked meshes: FF7 Limit Gauge's charge_loop.nif holds 3,050 shapes, one per particle sample, each shown for a single frame by its own NiVisController, including backdrop spheres up to 19,200 units in radius. FF7_LimitChargeLoop.hkx triggers it nine times, which used to load nine copies (27,450 meshes). Playback ran at about 2 fps and a plain library selection left the camera tens of thousands of units out. Changes:
- Repeats of one stateless mesh effect share loaded instances. A NIF with no particle systems, addon nodes or behavior graph draws the same whichever trigger shows it, so triggers whose lifetimes do not overlap reuse an instance (nine triggers, two instances here). Diagnostics state the count. Effects with particles or graphs still load once per trigger.
- Only actor shapes are marked for the engine's pose update. Effect meshes are placed by their own controllers, and the pose step was spending most of each frame on them.
- Visibility controllers with plain bool keys are flattened once, parent lookups and per-instance cue state are cached per frame, and hidden effect meshes are parked outside the frustum so the engine skips them early.
- After a scene rebuild the camera frames the selected subject (character by default) instead of the engine's fit over every mesh. Whole-scene and effects framing ignore effect meshes larger than the floor disc; they are still drawn, and Diagnostics says when this applies.

Verification on FF7_LimitChargeLoop under the live session: the profiler's 53 sampled frames are pixel-identical with the old loading path (SSE_NO_EFFECT_POOL=1 SSE_POSE_ALL_SHAPES=1) and the new one. Evidence is in verification/baked-effect. What remains is roughly 12 ms per frame of engine overhead for the 6,100 loaded meshes even while hidden.

## Sub-texture sheets

## Havok binary tagfiles
Some exporters save Skyrim SE clips as Havok 2010 binary tagfiles (first bytes CA B0 0D 1E, D0 11 FA CE) instead of packfiles. The game loads both; the renderer library's parser only reads packfiles, so these clips used to fail with "Unsupported HKX magic". HkxTagfile.cs reads the tagfile's self-describing type table and object stream and re-serialises the graph in memory as an hk_2010.2.0-r1 x64 packfile using the engine's SSE class layouts, so the clip catalog, annotation reader and pose import all keep consuming one format. The FF7 Cloud Animations 2hm_idle and 2hm_walk* files (interleaved animation, binding, annotation tracks, extracted reference frame) were the reverse-engineering corpus; each detail of the encoding is listed at the top of that file. Supported classes are the root container, animation container, interleaved and spline animations, bindings, annotation tracks and the default animated reference frame; a tagfile that carries other classes (a skeleton, a mesh) is reported by class name in diagnostics. Converted bytes never touch the original file.

Verification: --tagfile-smoke <file> converts the file, checks the packfile magic, decodes it, drops it into the library on the test-data Nord skeleton and confirms the pose changes between the first frame and mid-clip. All nine tagfiles in the supplied mods decode (41 to 49 frames, 99 tracks). Evidence is in verification/tagfile. Skyrim's own tagfile reader has not been compared byte for byte; the conversion is validated by decoding, not by the game.

## HDT-SMP physics
The PHYSICS group in the right column simulates HDT-SMP items with Bullet, the engine FSMP uses. Bones, constraints and collision are built from the physics XML the way the FSMP source builds them, so an XML and its collision meshes can be tested without starting the game.

**What gets simulated.**
- Armor, clothing, wigs and head parts whose NIF root holds the string "HDT Skinned Mesh Physics Object". The previewer reads the XML that string names from the mounted folders.
- Weapons. FSMP reads the physics link from armor and head parts only, so a weapon's strap or chain needs a carrier armor NIF whose XML names bones inside the weapon NIF. Equip that armor, or leave it off and the previewer uses any NIF in the weapon's folder whose XML names a weapon bone. A link string on the weapon NIF itself does nothing in game, and the Diagnostics tab says so.
- Models without a link, through `SKSE\Plugins\hdtSkinnedMeshConfigs\defaultBBPs.xml` when that file is mounted. Both map and remap entries are read.

**How it runs.** The simulation uses wall-clock time, as the game does. It keeps running while playback is paused and ignores the playback speed setting, so a paused pose settles under gravity. When a looping clip wraps, the previewer moves the whole simulation with the actor, so root motion does not tear it. After a seek, or a wrap where the pose itself jumps, it resets the simulated bones the way an FSMP reset does. Moving the weapon between hand and holster also resets its bones. Solver settings come from the solver section of `SKSE\Plugins\hdtSkinnedMeshConfigs\configs.json` when that file is mounted (numIterations, erp, min-fps, maxSubSteps). Without it the FSMP defaults apply: 10 iterations, erp 0.2, a 60 fps tick and 4 substeps.

**Controls.**
- **Simulate HDT-SMP physics** switches the simulation on and off. Off returns every bone to the animation alone. A render taken after switching off matches one taken before switching on.
- **Show collision shapes** draws each per-vertex-shape as spheres of radius margin times margin-multiplier and each per-triangle-shape as triangle outlines. A stub at each triangle's centre shows the margin on the collision side and, in red, the penetration depth behind it.
- **Show bones and constraints** draws the simulation's bones and a line for each constraint.
- **Reload meshes and physics XML** rebuilds the scene from disk. Edit the XML or export the NIF again, press the button, and the new version runs.
- The line under the button shows systems, bones, constraints, collision shapes, current contacts and the time one physics frame takes.

| Overlay colour | Meaning |
|---|---|
| Blue axes | Kinematic bone: mass 0, follows the animation |
| Orange axes with a ring | Simulated bone |
| Magenta line | Constraint between two bones |
| Cyan sphere, green triangle | Collider carried only by kinematic bones |
| Yellow sphere, yellow-green triangle | Collider with weight on a simulated bone |
| Red stub behind a triangle | Penetration depth |
| Red line with a cross | Contact found in the last physics step |

**Changes that also apply with physics off.**
- Bones that exist only in an armor or head-part NIF (cloth chains, hair strands) are merged into the skeleton under the matching parent, as the game does when it attaches the item. Before this, vertices weighted to them stayed at the bind position while the body moved.
- Shapes without a shader property are no longer drawn. Skyrim draws nothing for them, and on equipment they are collision proxies such as VirtualGround.

**Diagnostics.** Lines starting with "HDT-SMP:" list each system with its bone, constraint and collider counts, the solver settings in use, and everything the XML reader skipped. These messages are worth acting on:
- A shape named in the XML is not a skinned shape in the model. The XML binds shapes by name, so a renamed shape loses its physics in game without any error.
- A bone the XML uses is not on the actor.
- A skin bone has no `<bone>` line. The message names the default template it inherited and whether that made it kinematic or simulated.
- A constraint joins two kinematic bones and is skipped.
- A value is not a number. FSMP stops reading the file there and builds no physics for the item.
- A shape has more than ten colliders and every bone bound in its NiSkinData has radius 0. FSMP sizes its broadphase box from those bounds, so the shape may never collide in game.

**Differences from the game.**

| Feature | In the previewer |
|---|---|
| stiffspring-constraint | Approximated. FSMP solves it as a custom row inside the Bullet solver. The previewer solves the same row on its own before each step. |
| Non-Hookean spring terms | Not simulated. They need FSMP's modified Bullet. |
| `<pattern>` macros | Not expanded. A file that uses them builds no physics here. |
| Wind | Not simulated. |
| shared | One actor is simulated, so external never collides and internal behaves like public. |
| `<shape>` on a bone | Skipped. FSMP adds bone bodies with collision group 0, so these shapes never collide in game either. |
| defaultBBPs.xml | Implemented from the FSMP source and not yet run on real assets. The table in the mod list used for testing only maps ElinTail and ElinEar. |
| Precision | BulletSharp runs stock Bullet in double precision. FSMP runs its own Bullet build in single precision. Motion matches in character, not bit for bit. |

**Performance.** Bodies with more than ten colliders take their broadphase box from their bone bounding spheres, as FSMP does, and their vertices are skinned only when a pair's boxes overlap. Large collider-tree pair sets are tested in parallel and the results gathered in a fixed order, merge buffers and walk stacks are reused, a physics step re-skins only the meshes skinned to a simulated bone (or a bone below one), the write-back reuses each parent's inverse, and the overlay rebuilds its lines only after a physics step, a toggle or a camera change. In the Cloud test scene (skirt, wig and sword strap, 136 simulated bones) the paused physics step went from about 13.7 to 3.8 ms; during playback physics and render together stay at about 7 ms. `--smp-determinism <folder> <clip> <mod folders>` runs a fixed-timestep sequence and writes every simulated bone transform at full precision plus captures; the optimized build reproduces the previous build's output bit for bit. SSE_SMP_UNOPTIMIZED=1 restores the old collision order for timing comparisons.

**Verification.** `--smp-test` runs 49 checks that need no game files: transform conventions, the XML reader's order and template rules, a hanging and a dragged chain, sphere against triangle and sphere against sphere contacts, negative penetration, tags, weight-threshold and disable-tag. `--smp-smoke <clip> <mod folder> [<mod folder> ...]` mounts the folders over test-data, equips the weapon and armors that carry physics, and checks the build, the paused and playing simulation, sheathing, seeking, the overlay and the switch back to off. SSE_SMP_WEAPON picks the weapon by mesh name and SSE_SMP_NO_ARMOR=1 leaves the carrier armor off. Captures and logs from both runs are in verification/hdt-smp.

**Long runs.** Physics writes only a simulated bone's rotation and translation back to its node; the node keeps the scale its animation gives it, as FSMP's writeTransform does. Before 2026-10-02 the previewer also wrote the scale it had just read and read it back next frame. Along constraint chains the mismatch compounded during fast motion. Within seconds of looping a dodge, the Fusion Sword strap's bones reached thousands of times their size. Their mass was rescaled to match, and the strap mesh skinned to them filled the scene. `--smp-soak <folder> <minutes>` replays the live session at a fixed 1/60 s step and logs, every simulated second, the worst constraint-link stretch, bone scale range and speed. It stops early if a link grows by 100 units or a bone's scale leaves 0.5 to 2. SSE_SOAK_CLIP=<path suffix> picks another library clip. SSE_SOAK_QUEUE=1 plays the saved queue, SSE_SOAK_JITTER=1 varies frame times and SSE_SOAK_SCRUB=1 adds scrubbing. SSE_SOAK_TRACE=<system xml> writes every bone of one system at every step. With the Cloud session (AC skirt and wig, Fusion Sword strap) the old build blew up after 14 s of DodgeBack. The fixed build ran 5 minutes on each Dodges clip, the queue, scrubbing and jittered frame times. Bone scale stayed between 0.88 and 1.14, the animation's own, and the worst stretch did not grow from minute to minute.

## FF7 Limit Gauge effects (PIE.@FF7VFX)
The previewer plays the FF7 Limit Gauge plugin's own annotation, which spawns an effect NIF with an offset and a rotation from the actor's root, or on the weapon. Payload Interpreter ignores it in game; the plugin handles it.

```
PIE.@FF7VFX|<nif under meshes>|root, follow or weapon|<seconds>|<x>|<y>|<z>[|nine rotation numbers, by rows]
PIE.@FF7VFXEND|<nif under meshes>
```

- **root.** One spawn where the actor root stands when the annotation fires: x right, y forward, z up, in game units. A NIF point p goes to R*p + offset, R being the nine numbers (identity when absent). It stays in the world and does not follow the actor. It is shown for `<seconds>`.
- **follow.** Like root, with the same offset and rotation, but kept on the actor: it moves and turns with the actor's root for its `<seconds>` and plays once. The plugin uses it for the limit-start lightning, which it spawns itself, so no clip carries it yet.
- **weapon.** The NIF is authored in blade space (origin at the grip, blade along +Z). It follows the WEAPON node, turned so +Z runs along the blade. The blade axis is found as the plugin finds it, from the dominant axis of the weapon model's bound (+Y when the bound says nothing). It is spawned again every `<seconds>` until `PIE.@FF7VFXEND` with the same NIF, or for 12 s.
- Times follow the clip's MCO_AttackSpeed like every other annotation. The plugin's fScale setting is taken as 1.

Not confirmed in game: the plugin's rotation reading and weapon axis were unverified when this was written, so the previewer shows what the annotation says, not what the game has been seen to do.

**Verification.** `--ff7vfx-smoke` loads the Portable session and the three Limit Break clips of the FF7 Limit Gauge mod and runs 37 checks: one effect per root annotation, each at root + offset turned by its matrix and staying put; weapon effects on the WEAPON node with +Z on the blade axis; respawn counts against their END (Limit03_Sword_01: two spawns from 0 s at 1.6 s each until 1.72 s); every NIF found. ## Precision attack collisions
Tick **Show Precision attack collisions** (PRECISION group, off by default) to draw the capsules Precision builds from the selected clip's `Collision_*` annotations. Red is the attack capsule and blue the recoil capsule, the colours Precision's own debug view uses. Each capsule rides its bone and the root motion, appears at its Collision_Add and goes at whatever ends it. The label under the box lists every collision with its time span and size. The Annotations & effects tab lists the timeline with the reason each collision ends, plus anything Precision would ignore or reject. The box and the player/NPC choice are saved with the session.

The rules are taken from the Precision 2.0.4 source (PrecisionHandler.cpp and AttackCollision.cpp, https://github.com/ersh1/Precision), not from the documentation:

- Collision_AttackStart (or Collision_Start) opens the attack. Add, Remove and ClearTargets before it are ignored. Event names and payload parameter names ignore case.
- Collision_Add needs Node(). The bone lookup ignores case, as the game's GetObjectByName does, but only `WEAPON` and `SHIELD` in capitals get weapon sizing.
- Collision_Remove.Node() removes the first collision on that node, and this comparison is case sensitive.
- Collision_Remove.ID() calls `remove_if` and then `erase` with one iterator. The documentation says it removes every collision with that ID; the code removes all of them only when another collision comes after them in Precision's list. Two ID(1) collisions at the end of the list lose one and keep the other. The previewer reproduces this and the Annotations tab says when it happens.
- Collision_AttackEnd, Collision_Cancel, attackStop and staggerStart remove every collision and close the attack.
- Duration(x) ends a collision x seconds after it starts. Duration(0) uses fDefaultCollisionLifetime, times fDefaultCollisionLifetimePowerAttackMult for a power attack. The previewer treats a clip as a power attack when its file name contains "power".
- hitFrame removes the first remaining recoil capsule when bRemoveRecoilOnHitframe is on. NoRecoil and WeaponTip collisions get no recoil capsule.

Sizes, in game units:

- WEAPON. Precision measures the weapon model: the merged bounding sphere of its visible geometry, radius plus the centre's distance along the blade. The previewer reads the same spheres from the weapon NIF. Length is that reach (or Length()) times fWeaponLengthMult, LengthMult and Scale, and never below fMinWeaponLength times the same multipliers. Radius is fWeaponCapsuleRadius (or Radius()) times RadiusMult and Scale. The capsule runs from the weapon node along the blade. WeaponTip moves it out by length minus radius.
- SHIELD takes fMinWeaponLength, because the previewer has no left-hand model.
- Any other node uses the capsule collision on that bone in the skeleton NIF (the vanilla skeleton has 19), or Precision's built-in hand capsule when the bone has none. The length is scaled by fWeaponLengthMult, Length(), LengthMult and Scale. As in Precision, Radius() only rescales the length; the drawn radius is the bone's own.
- Rotation() (degrees, X then Y then Z) and Translation() place the capsule's node relative to the bone.
- **Sized as the player** applies fPlayerAttackLengthMult, fPlayerAttackRadiusMult and bRecoilPlayer. **Sized as an NPC** uses bRecoilNPC and no extra multipliers.

Settings are Precision's defaults until a mounted mod supplies `MCM\Config\Precision\settings.ini` or `MCM\Settings\Precision.ini`. Both are read, in that order, as the plugin reads them. The label names the files in use.

| Precision feature | In the previewer |
|---|---|
| Trails, TrailMeshOverride, trail colours | Not drawn. |
| DamageMult, GroundShake, ClearTargets | No visual. They appear in the Annotations tab. |
| weaponSpeedMult | Taken as 1, so durations are not divided by weapon speed. |
| Per-weapon radius overrides in Precision's toml files | Not read. |
| Actor scale, mounts, first person | Scale 1, on foot, third person. |
| Clips without Collision_* annotations | Precision adds default collisions on weaponSwing and similar events in game. The previewer draws nothing for them. |
| Shield and bow bashes | Not modelled. |
| Queues | The queue skips a clip's annotations after its hand-over, so a Remove or AttackEnd placed after MCO_WinOpen never fires and the collision carries into the next clip. |
| Expiry | A Duration collision ends exactly at start plus duration. The game ends it on the first frame after that. |

## Background mode
`--background` (or the environment variable SSE_PREVIEW_BACKGROUND=1) opens the previewer off-screen, out of the taskbar and never as the foreground window. Rendering is unchanged: captures taken this way are pixel-identical to a normal run. It is meant for test and tool runs, for example `"SSE Animation Previewer.exe" --background --clip-profile <clip path suffix> <name>` or `--background --mod-sweep <source folder substring>`, which read the session beside the exe and write their output under clip-profile or mod-sweep next to it. Tool and test modes save to verification-session.json and never to your session.json. Close a background instance from Task Manager if a run is interrupted; it has no visible window.

## Development
The previewer source is in src. Renderer and dependency source is in engine and native. scripts/build-portable.ps1 publishes a self-contained Windows x64 folder and copies the native C++ runtime. It requires development tools only when rebuilding, never when running the delivered application.

Upstream renderer changes include safe color conversion, direct interleaved HKX decoding, stored-track interpolation, world-space model/view composition, a presentation cap, render diagnostics and scene hooks. See source-patches and THIRD-PARTY-NOTICES.md.

Armor addon skin textures: male/female NAM0/NAM1 TXST links are applied to SkinTint shaders with isolated texture blocks. Per-shape MO2S/MO3S alternate textures and NAM2/NAM3 swap lists remain unsupported.

Particle collision: native planar and spherical collider chains support swept point contacts, bounce, die-on-collide and linked spawn modifiers. Original collision fixtures are included in Samples/ParticleFixtures. Contact timing and 30/60 FPS determinism are checked locally. Moving-surface velocity, particle-radius contacts and exact Skyrim bounce semantics remain unverified and are reported in diagnostics.
NiPSysBombModifier: signed spherical/cylindrical/planar forces and active-state gating are simulated. AE 1.6.1170 static inspection verifies linear/exponential equations and the full-distance cutoff; transform and scheduling parity still need comparison. Included bomb-inward and bomb-disabled NIF fixtures allow a direct visual comparison.

Inherited particle motion: BSPSysInheritVelocityModifier samples source-origin motion at birth, including external actor/effect placement, with chance/multiplier/variation controls. Local-space conversion and deterministic seeking are tested. AE 1.6.1170 static inspection verifies relative multiplier variation and direct source-origin velocity addition; update cadence, RNG sequences and child-spawn scheduling remain unverified. The optional Follow scene camera keeps moving effects framed; Alt-drag or wheel input switches to manual control, and F frames the current scene.

Camera following starts enabled. With a clip loaded it tracks the actor root, the point root motion moves (the amber arrow): the camera keeps its angle, distance and offset and moves by however far the root moves, so a dodge or combo travels without the view re-framing or zooming. Framing (F, a rebuild) or panning sets a new offset. Orbiting, panning and zooming by hand leave Follow camera ticked, and the camera keeps travelling with the root from the new view. With Root motion clear the root stays at the origin and so does the camera. An effect preview has no actor, so there following tracks current visible bounds and only increases distance as the scene grows, which avoids zooming back and forth as particles expire. Moving the camera by hand in an effect preview holds that view, still with Follow camera ticked, until the scene is framed again (F, a rebuild, or ticking Follow camera again). The camera zooms in to 2 units from its focus point (the engine's default limit of 20 stopped short of a face or a hand); pan to move the focus onto the part you want to approach. Use the camera selector to frame the whole scene, the character, or effects. F and automatic following use that selection; a missing subject falls back to the whole scene. Character framing keeps large effect layers from shrinking the actor to a tiny silhouette. Framing accounts for viewport aspect ratio and current projected-speed particle stretch, and excludes hidden particle systems and zero-alpha particles. The selector changes framing only, not visibility or simulation.
Gravity now applies AE's native 1.6 strength multiplier and exponential decay. Planar decay uses perpendicular distance to the source plane; spherical decay uses distance to the source. The original gravity-decay.nif fixture exercises the serialized path. Gravity turbulence adds native per-axis random acceleration (Turbulence × Turbulence Scale × 500), including the AE spherical-decay branch behavior. Samples are deterministic at 120 Hz; Skyrim RNG sequences and frame cadence remain unverified. WorldAligned uses the source local rotation for the axis, with the transformed origin retained for decay, following the AE branch; complex scene-transform parity still needs game comparison. No game-render equivalence is claimed. Paired gravity-turbulence-on/off NIF fixtures are included.

Emitter sources: the effect panel now offers a per-system mesh picker for explicit preview overrides. Select geometry from the effect NIF, apply it, or restore the authored references. Overrides never edit the source file and reset particle simulation for repeatable replay. Emitter controllers still govern birth rate and visibility. This is an authoring/test facility, not automatic emulation of Skyrim's runtime mesh bindings. Overrides are discarded when the scene is rebuilt.

Particle LOD: the normalized test-distance control applies BSPSysLODModifier's emission and birth-size scales. Zero defaults to full detail. Changing this control restarts the preview using the selected fixed distance. The included particle-lod.nif fixture demonstrates fewer, larger particles at its far setting. Automatic camera/fade-category mapping, fade-node bypass flags, changing-distance scheduling and child-spawn parity remain incomplete; this control does not claim to reproduce Skyrim's automatic LOD decisions.

Dropped HKX files remain in the library across source refreshes and are saved with the session. Restore session reloads their DAR/OAR context from adjacent configuration files. Missing files are reported in diagnostics and their saved paths are retained so they can return on a later refresh.

Animation payloads now honor @UNAPPLYSPELL for visuals originating from @APPLYSPELL. Delayed removals use their scheduled absolute time, stop all art from that application, and allow later applications to render again. Backward seeking restores the earlier visual state. Effects without a supported loaded behavior graph currently use an immediate visual cutoff. Supported flat effect graphs now play their authored shutdown, as described below. Repeated active applications are suppressed, and manual trigger invocations now share the animation event timeline. Source reference: PluginTemplate/PayloadInterpreter/src/payloadHandlers/spellApplyHandler.cpp (Actor AddSpell/RemoveSpell). Verification: verification/ability-removal contains rendered before/after frames and regression results.

Effect graph shutdown:
- The previewer reads a NIF's BSBehaviorGraphExtraData project, follows its character and behavior files through the mounted assets, and supports a validated flat state machine of Gamebryo sequence generators with unconditional zero-duration transitions. This includes the tested vanilla Magic\BeginLoopEnd.hkx chain.
- Authored NIF text keys drive state transitions. StopEffect is delivered once at art lifetime expiry or an applied ability's removal. The selected ending sequence controls shader alpha, transforms, and particle controller values; EndAnim removes the effect. AE's strict three-second shutdown watchdog is used when no completion event arrives.
- Missing sequences and unavailable/unsupported graphs are reported. Arbitrary nested graphs, conditional transitions, transition blending, behavior modifiers, and character behavior execution are not implemented. Runtime state, frame scheduling, and native blend-channel retention for missing sequences still require comparison; no exact game-render parity is claimed.

### HDT-SMP source map
- SmpMath.cs holds the rotation, origin and scale transform that mirrors FSMP's btQsTransform, with conversions to the renderer's and Bullet's row-vector matrices.
- SmpCollision.cs ports hdtCollider, hdtSkinnedMeshShape, hdtSkinnedMeshBody and hdtSkinnedMeshAlgorithm: the collider tree keyed by bone indices, the sphere and triangle tests, and the merge of contacts onto bone pairs.
- SmpPhysics.cs holds the XML reader (hdtSkyrimSystem), bones (hdtSkyrimBone), the world settings and the frame and substep loop (hdtSkinnedMeshWorld, hdtSkyrimPhysicsWorld). Contacts enter Bullet as hand-built manifolds, as in the plugin. Bullet derives a kinematic body's velocity from its interpolation transform, so each substep places that transform one step behind the body to hand the solver the frame velocity the plugin computes.
- ScenePhysics.cs connects it to the scene: physics links, the carrier search for weapons, bone lookup across the skeleton and the weapon NIF, write-back into the skeleton's physics layer, and loop and seek handling.
- SmpDebugDraw.cs draws the overlay. SmpTests.cs holds the `--smp-test` checks.
- FSMP details kept on purpose: a skin bone without a `<bone>` line takes the mass of the default template in force at that shape but none of its other settings, and collision reads a bone with centerOfMassTransform applied on the other side than the rest of the code does.

Sources, Recent scenes and floor shadows (September 29)
-------------------------------------------------------
Loaded Sources now has correctly measured wrapped rows and its own vertical scrollbar. Drag the divider above its heading to enlarge the source panel. Resizing the left panel recalculates row heights rather than clipping lines.
Scenes > Recent lists the latest 12 successfully loaded or saved scenes, newest first. Reopening a scene moves it to the top. Entries show their full folder to distinguish duplicate filenames; missing scene files offer the existing replacement picker. History is stored in recent-scenes.json and retained during portable updates. Restore session does not add the autosave file to scene history.
The grid floor enables the renderer's existing world-Z=0 ground shadow receiver, so animated characters and equipment cast shadows onto the grid. Hiding the grid disables its receiver. Lighting controls still govern shadow casting and lighting. Validated with floor-shadow on/off render comparisons at two animation poses.

Performance update: repeated particle placement and ADDN attachment evaluations are reused within each scene update. The Cloud weapon-art test averaged 23.25 ms versus 98.52 ms previously across the effect-heavy samples, with unchanged particle counts. This capture benchmark includes bitmap readback and does not guarantee 60 FPS on all effects or hardware.

The default ground uses the user-supplied Test Room testgrid_d.dds, testgrid_n.dds, and testgrid_s.dds, bundled under Resources. It starts enabled and Reset enables it; saved scenes retain their own visibility choice. The material tiles every 512 Skyrim units and uses the lighting rig, normal/specular maps, and the existing ground-shadow receiver.
